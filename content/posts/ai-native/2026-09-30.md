## 1. Agent Factory recap: Agent harnesses, shifting left, and autonomous coding

- **作者/来源：** Mollie Pettit、Smitha Kolan / Google Cloud
- **发布日期：** 2026-09-25
- **原文：** https://cloud.google.com/blog/topics/developers-practitioners/agent-factory-recap-agent-harnesses-shifting-left-and-autonomous-coding

**推荐理由：** 这篇把 coding agent 的提升路径讲得很具体：不要把失败当成“prompt 不够好”，而是持续把经验前移到 repo context、tools、linters、tests 和 evals 中。它同时给出 linear harness、closed-loop repair、guardrail hooks 等可操作模式，适合用来校准团队级 harness 应该建设什么。

**核心要点：**
- Harness 是模型之外让 Agent 成功的完整环境。仓库里有结构化文档、清晰接口和可发现工具后，开发者可以减少手工塞 context，让 Agent 自己完成 grounding；目标从“prompt engineering”转向“environment engineering”。
- Agent 失败后的修复应该不断 **shift left**：从重试 prompt，逐步变成 repo docs / AGENTS.md、linters、tests，再到 upstream evals。团队规范只有进入可自动执行的环境约束，才会成为可复用能力，而不是依赖个人提醒。
- 长时程自治需要缩小每一步的状态空间：用小而可审查的 PR 串联高置信度变化；需要迭代修复时采用 edit → test → diagnostics → retry 的 closed loop，并设置迭代上限和执行 guardrail。长期投入应放在 **tools + context**，而不是过度定制容易随模型进步过时的 harness 框架。

> 核心启示：**团队 Harness 的真正复利来自把人的纠错经验逐层固化成 context、tool 和 deterministic verifier；模型可以替换，这些工程资产会持续积累。**

## 2. State of agent skills

- **作者/来源：** Amelia Charles、Andrew Qu、Jonathan Hefner / Vercel
- **发布日期：** 2026-09-25
- **原文：** https://vercel.com/blog/state-of-agent-skills

**推荐理由：** 这是少见的基于真实 registry 数据观察 Agent Skills 生态的文章。skills.sh 在七个月内达到 **100 万个 skills、接近 2.8 亿次 installs**；更重要的是，数据开始揭示 Skill 的价值到底来自哪里，以及下一阶段为什么会从“公开 prompt 文件”转向组织自己的 judgment、测试和维护体系。

**核心要点：**
- Skill 的本质是把“这件事应该怎么做、什么叫做好、如何判断结果”显式化成可复用的软件资产。公共生态增长极快，但供给仍偏技术，而真实安装需求已经扩展到业务运营、写作等更多工作。
- Agent workflow / automation 占分类样本 installs 的 **14.8%**，仅次于软件工程；同时分布高度集中：只有 **375 个 skills（约 0.04%）贡献了 62% installs**，top 1.2% 贡献 94%。跨行业可复用的 skills 占 **87.5% installs**。
- 下一阶段的差异化会转向公司内部 judgment。Skill 的评价标准也会从 install count 转向 **with-skill vs. without-skill 的实际效果**，并逐渐配套 tests / benchmarks，像代码一样被版本化和维护。

> 核心启示：**Skill 正在从“可分享的提示词”变成新的软件资产层：公共 Skills 提供通用能力，组织私有 Skills 承载差异化 judgment，而 Evals 决定它们是否真的有价值。**
