## 1. Improved token efficiency for longer agent runs

- **作者/来源：** Jediah Katz、Connor O’Keefe、Calvin Yee / Cursor
- **发布日期：** 2026-09-23
- **原文：** https://cursor.com/blog/improved-token-efficiency

**推荐理由：** 这篇不是泛泛讨论“压缩 prompt”，而是 Cursor 基于真实生产流量对 agent harness 做的一组系统级优化。随着任务变长，成本越来越来自每轮重复携带的 system prompt、tool definitions、文件内容和历史 context；Cursor 因此把优化对象从单次输出 token 转向 **整条 agent trajectory 的 context 生命周期**。多项改动叠加后，用户 token 成本降低约 7%，且没有观察到质量下降。

**核心要点：**

- **静态 context 应只保留真正高频且必须从一开始可见的信息。** 随着模型能力增强，Cursor 删除了大量过去用于约束模型行为的冗长说明，system prompt 缩短约 **66%**。他们强调真实流量上的 A/B test 比只看高难度 eval 更重要，因为 benchmark 往往不能代表真实请求分布。
- **Tools 应按需进入 context，而不是因为“可用”就常驻。** Cursor 发现大多数内置工具出现在不到 20% 的会话中，于是把低频工具改成动态加载；此前对 MCP tools 使用同样方法时，调用 MCP 的会话总 token 使用降低 **46.9%**，这次进一步让 built-in tool descriptions 的静态 context token 减少 **60%**。同时，通过更稳定的 prompt prefix 与 cache breakpoint，cold cache miss rate 又降低了 **20%**。
- **文件读取和 subagent 都是 context topology 问题。** Read 从每行带行号改成每 10 行标一次，单独就减少 **1.6% cache-read tokens**；subagent 则通过独立 context window 隔离探索成本，但也会带来重复工作和协调税。Cursor 因而取消了“强制多用 subagent”的 prompt，并把跨模型调度限制为用户或 harness 明确要求时才发生。

> 核心启示：**长时程 Agent 的单位经济学主要由 harness 决定。一个实用的优化顺序是：shrink static instructions → dynamically disclose tools → stabilize cacheable prefixes → compress repeated evidence → isolate expensive exploration with subagents。Context engineering 应该像 runtime 性能工程一样被持续测量和 A/B。**

## 2. RRSI: Regularized Recursive Self-Improvement of Agent Harnesses

- **作者/来源：** Peng Xia、Rujun Han、Zifeng Wang、Yanfei Chen、Yufan Zhang、Yoonho Lee 等 / Google Cloud AI Research、UNC、Stanford
- **发布日期：** 2026-09-21
- **arXiv：** https://arxiv.org/abs/2609.24972
- **AlphaXiv：** https://www.alphaxiv.org/abs/2609.24972

**推荐理由：** 最近越来越多工作让 Agent 根据失败 trajectory 自动修改自己的 prompt、tools、skills、memory、control flow 和 context policy，看起来已经接近一种 harness-level recursive self-improvement。但这篇指出一个非常关键的问题：**如果始终在同一小组 evolve tasks 上提出、测量、选择修改，系统很容易把 benchmark-specific tricks 当成“能力进化”。** RRSI 的贡献不是限制 Agent 能改什么，而是对“进化过程本身”做 regularization。

**核心要点：**

- **Harness evolution 本质上是高容量、反复自适应的搜索，因此天然容易过拟合。** Backbone model 在实验中保持冻结，而 harness 可以修改 prompt、control flow、tool interfaces、memory、skills、subagents 和 context management。每轮都根据同一 evolve set 的 trajectory 产生候选修改，再在同一批任务上选择赢家，这与反复查看 validation set 后调参类似，会逐渐吸收 task leakage、随机评测噪声和无效复杂度。
- **RRSI 同时 regularize proposal 和 selection。** Proposal 侧用逐轮收紧的 edit budget 限制一次能打包多少独立修改，并记录历史证据做 credit assignment，在搜索停滞时主动探索未尝试的 harness component；selection 侧增加 benchmark leakage critic、基于基础重复实验估计的 noise floor、performance/cost 联合门槛以及 structural pruning，让没有持续证明价值的机制被删掉，而不是永久堆积。
- **真正衡量“进化”的指标是未见任务迁移，而不是 evolve-set 分数。** 论文覆盖 coding、agentic workspace 和 engineering design 共 8 个 benchmark；相较未正则化 evolution，RRSI 在 evolve split 上最高提升 **14.1 points**，在 5 个 OOD benchmarks 上最高提升 **4.7 points**，同时最终 harness 使用的 policy tokens 少约 **30%**。论文还报告所有 held-out splits 都没有回退。

> 核心启示：**Agent harness 的自我进化应该更像一套带 held-out eval 的 CI/optimization system，而不是持续在同一 benchmark 上 hill-climb。可复用的方法是：trajectory evidence → sparse candidate edits → leakage/noise checks → cost-aware selection → held-out transfer eval → prune/rollback。真正的“skill/harness evolution”必须证明改进能离开它出生的任务集。**
