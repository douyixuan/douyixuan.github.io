今天选取两篇本周原创工程文章：一篇研究如何验证大型生产系统迁移，一篇研究如何训练代理之间的有效通信。

## 1. Migrating our Messages API to Rust

- **作者/来源：** Lance Martin、Jake Eaton、Arvin Aminpour、Emma Webb、Bharat Mediratta、Ravi Trivedi / Anthropic Engineering
- **发布日期：** 2026-11-25
- **原文：** https://www.anthropic.com/research/migrating-api-to-rust
- **相关技术：** Rust、Shadow Traffic、Differential Testing、Agent Harness

**推荐理由：** 当生成代码比确认行为正确更容易时，可以把仍在演化的旧系统作为参照，构建代理能够自主利用的差分验证信号。

**3 条核心要点：**

1. **测试通过不等于生产行为一致。** 约 700 个既有集成测试在迁移中出现逾 100 个被弱化的断言；4 月 Rust 版本约 98% 测试通过，却只有约四分之一的线上输入匹配。生产请求分布与测试覆盖必须分别衡量。
2. **控制非确定性与隐私。** 模型只运行一次，输出同时供两版 API 比较；用逐阶段检查点和差异指纹代替客户原始文本，归类差异并委派代理处理。沙箱内用合成请求复现问题，局部比较不到一秒；PR 人工审查后再以影子流量验证。
3. **把反馈沉淀为规则与检查。** 将评审纠正写入共享记忆、测试、Lint 和双版本同步门禁。迁移后作者报告每请求 CPU 下降约 70%，首 Token 中位时延下降约 20%；这是单一生产迁移案例，并非普适收益或形式等价证明。

> **核心启示：** 编码代理的速度取决于能否获得快速、准确且独立的验证反馈。

## 2. Swarms, Flocks, Gangs: How to build, train, and evaluate multi-agent systems

- **作者/来源：** Ben Burtenshaw、Kashif Rasul / Hugging Face
- **发布日期：** 2026-11-26
- **原文：** https://huggingface.co/blog/training-swarms
- **相关技术：** TRL、vLLM、Multi-agent RL、Qwen3-0.6B

**推荐理由：** 用可复现的小型实验将协作收益与额外采样成本区分开，先检验模型能否学会共享信息，而不直接假定增加代理就会提高能力。

**3 条核心要点：**

1. **共享权重、独立上下文。** 四个代理各持一个私有整数，至少一人给出完整排序才算成功。共用 Qwen3-0.6B 策略，利用团队正确性与生成 Token 惩罚训练；每题采样八组团队轨迹，同组成员共享团队优势。
2. **训练使通信更有效。** 75 次更新中，首末五批训练成功率由 6.6% 增至 82.3%，平均生成 Token 下降 37.4%；留出题通过 26/32。广播反而增多，说明消息数量不能直接衡量通信成本；留出集 Token 效率未记录。
3. **不能将练习任务外推为通用协作优势。** 单代理无法取得全部私有信息，故本实验未完成单代理与多代理的等预算比较。原实验使用八张 H200，教程提供两张 H200 的复现配置；教程与原实验批量不同。

> **核心启示：** 先用可验证任务测量协作机制，再在相同预算、相同信息可达性下比较单代理和多代理。

## 今日思考

将验证信号视为 Agent 系统设计的一部分：生产迁移需要快速局部复现、线上对照和人工审查；多代理训练需要任务判定、成本约束和独立留出集。不要仅用生成量、通信量或一次成功衡量系统能力。
