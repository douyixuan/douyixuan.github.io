今天选取两篇本周原创文章，均发表于 11 月 23 日（论文为 UTC）。主题是如何维护 Agent 的评测系统：既要保证测量有效，又要让测试跟上能力变化。

## 1. How to build and maintain an agentic evaluation

- **作者/来源：** Avijit Ghosh、Ben Burtenshaw、Irene Solaiman / Hugging Face
- **发布日期：** 2026-11-23
- **原文：** https://huggingface.co/blog/agentic-evals
- **相关技术：** Harbor、Terminus-2、ATIF、Oracle、Regression Eval

**推荐理由：** 文章以拉曼光谱拟合任务展示如何从能力主张出发，复用已有任务、构造可重复执行的环境、检查评分器并分析失败轨迹，适合用作 Agent Eval 的开发与维护指南。

**3 条核心要点：**

1. **先测评测器，再测模型。** 复用 Terminal-Bench 的 raman-fitting，构建八个合成光谱开发任务；要求参考解通过、空操作失败，并测试错误解和合法替代解。仅检查缺陷比会让跳过拟合的捷径在八题全部通过，因此补充拟合结果检查。
2. **重复成功和至少成功一次不同。** gpt-oss-120b 在 24 次运行中通过 11 次，pass@3 为 7/8，三次全通过仅 1/8；19 次首轮即发出完成指令，其中 11 次未产生结果文件。应保留轨迹并按任务聚类估计误差；八个开发任务不能代表未知任务分布。
3. **持续维护而非一次性发布。** 固定模型、提供商、环境、工具和评测版本，公开可审计的开发集、评分器和变更记录，保护活跃留出题目并提供受控审查途径；题目保密本身不能阻止饱和。

> **核心启示：** 评测器也是需要正负对照、版本记录和回归测试的软件。

## 2. Self-Evolving Evaluation Environments for Computer-Use Agents

- **作者/来源：** Wenhao Wang、Panrong Tong、Quyu Kong、Pengxiang Li、Haowen Yang、Chenglin Cai、Siheng Chen、Yue Wang / Alibaba Token Hub、浙江大学、上海交通大学
- **首次提交：** 2026-11-23 16:32:01 UTC（北京时间 11 月 24 日）
- **原文（arXiv）：** https://arxiv.org/abs/2611.30962
- **AlphaXiv：** https://www.alphaxiv.org/abs/2611.30962
- **相关技术：** CUA-SEE、Computer Use Agent、CanonicalState、Adaptive Evaluation

**推荐理由：** CUA-SEE 将评测任务和可执行验证器纳入由实际执行轨迹驱动的演化循环，把群体基准的扩展与单个 Agent 的能力边界诊断分开，避免只追求更难的任务。

**3 条核心要点：**

1. **分离通用基准与针对性诊断。** 多模型同源轨迹校准任务难度和软件功能覆盖；单模型诊断则在不确定能力边界附近上下探测，区分有效失败、环境故障和步数耗尽。任务演化保留语义谱系并要求新增可观测义务。
2. **检查点由环境真实状态支撑。** 软件适配器将原生状态导出为 CanonicalState，隔离信息的 verifier agent 将需求拆成原子检查点，pass agent 独立生成合法完成状态，再用正负状态及对抗审查校验；不能仅凭 Agent 自述判分。
3. **动态基准不等于固定尺度。** 作者报告五个代理、四轮演化中宏平均分由 60.6 降至 47.5，平均步骤由 27.4 增至 39.3，精确功能覆盖增至 3.65 倍；检查点与人工轨迹判断的一致率为 84.0%。变化说明任务变难、覆盖扩大，并非模型能力下降；验证器仍存在误判。

> **核心启示：** 用共享基准追踪总体能力，用受控诊断探测个体边界，分别报告结果。

## 今日思考

将 Eval 作为独立、版本化的工程制品：**Capability Claim → Task/Environment → Oracle/Negative Controls → Rollout Evidence → Boundary Probes → Verifier Audit → Versioned Benchmark**。保留固定锚点与独立留出集作为跨版本比较依据；不要让自动演化同时任意改变题目、评分标准和能力主张。

**证据边界：** Hugging Face 的示例为八个开发任务；CUA-SEE 为作者报告的预印本实验，未独立复现。arXiv 元数据与 HTML 正文已核对；AlphaXiv 文献服务已返回匹配全文，但标准网页独立访问未成功。
