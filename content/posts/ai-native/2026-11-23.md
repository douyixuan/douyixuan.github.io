今天选择两篇**过去七天内首次提交的原创研究**。它们不把 Agent 的错误简单归咎于模型能力，而是分别在**跨任务上下文隔离和共享工作区整合**、**单任务执行的循环与完成判断**上设计运行时控制。两篇均为 2026 年 11 月的 arXiv 预印本，实验数据为作者报告，尚未独立复现。

## 1. Context as a Resource

- **作者/来源：** Xufei Tian、Han Hu、Wenli Du / 华东理工大学
- **首次提交：** 2026-11-19 16:19:56 UTC（北京时间 2026-11-20 00:19:56）
- **原文（arXiv）：** https://arxiv.org/abs/2611.26346
- **AlphaXiv：** https://www.alphaxiv.org/abs/2611.26346
- **论文 HTML：** https://arxiv.org/html/2611.26346v1
- **代码与复现实验：** https://github.com/Viacol0916/ClonAct
- **相关技术：** Agent Harness、Context MMU、Context Cells、Git Worktrees、Trial Merge、Shared Prefix、Prompt Caching

**推荐理由：** 多个任务共用一个长期 Agent 会话时，后到的“只读”限制可能污染正在进行的写操作；改用“路由器→自然语言工单→子代理”则可能丢失原始需求细节，并在独立分支合并时出现最后一公里错误。论文把上下文视为可调度资源，提出 ClonAct：用非生成式控制面转发消息，保持澄清到执行的连续上下文，并在合入共享代码前进行冲突检测与隔离测试。它直接讨论 Agent-native 平台的会话、工具边界和代码整合问题。

**3 条核心要点：**

1. **将上下文调度与生成式分工分开。** 非生成式 Context MMU 将事件路由到独立 Context Cell；每个 Cell 保留统一 Shared Trunk、直接与用户对齐的 Intent Spine 和独立工具历史。澄清阶段由工具执行器强制只读，确认后才挂载 Git worktree 并原地进入执行，减少重新生成工单造成的意图失真。Shared Trunk 的字节稳定性利于前缀缓存，但不能证明不同会话共享底层 KV 张量。
2. **共享仓库修改必须经过合并门禁。** Synaptic Bus 按文件、Python AST 符号和资源足迹传播相关状态；合并前区分无冲突快速通道、显式冲突协调、共享符号的语义联合回归测试。十组真正编辑冲突任务、每组三次的对比中，传统路由工作流最终联合通过率平均为 **33.3%**，加入机制后的 ClonAct 为 **63.3%**；同等质量的“路由器+试合并门禁”也能达到这一水平，ClonAct 另外减少 **45.9%** Prompt Token。这组仅十个独立冲突任务的配对检验 **p=0.156**，不能宣称差异已达到通常统计显著性。
3. **并发吞吐与计费不能只看 Token。** 在无代码合并冲突、2.5 倍事件涌入的三条模拟流中，ClonAct 完成率 **95.0%（57/60）**，中位等待 **53.6 秒**，状态查询无超时。相较生成式路由方案，Surge 场景总 Prompt Token 少约 **45.1%**，但两级 API 计费因非缓存入口分类调用，实际费用可能接近持平。实验还受固定模型、Python AST 分析粒度、少量流与未覆盖“持续涌入+真实合并冲突”的组合场景限制。

> **核心启示：** 在多任务 Software Factory 中，把 Intent Context、工具权限、共享代码足迹与合并后测试分成独立控制面；不能把工作分支内部测试通过直接视为最终交付。

## 2. CANDID: Candidate-Driven Intervention for Disciplined Execution in Local Computer-Use Agents

- **作者/来源：** Woongkyu Lee、Jungwook Choi / Hanyang University
- **首次提交：** 2026-11-17 15:39:11 UTC（北京时间 2026-11-17 23:39:11）
- **原文（arXiv）：** https://arxiv.org/abs/2611.24977
- **AlphaXiv：** https://www.alphaxiv.org/abs/2611.24977
- **论文 HTML：** https://arxiv.org/html/2611.24977v1
- **相关技术：** Computer-Use Agent、OSWorld、GUI Action、Loop Recovery、Unanimous DONE Gating、Test-Time Sampling

**推荐理由：** 资源受限的本地 GUI Agent 不一定缺少正确动作候选，而可能在关键节点持续选择同一个失败动作，或未完成任务就输出 DONE。CANDID 不改模型参数，也不在每一步要求模型生成文字反思，而只在检测到重复动作或终止提议时额外采样并过滤候选动作。这给“何时继续、何时停止”提供了一种轻量的 Harness 层控制方案。

**3 条核心要点：**

1. **只在高风险节点干预。** 当规则检测到重复动作，采样四个附加动作并剔除重复、不可执行、匹配原错误模式的候选；当模型提议 DONE，则只有**全部有效候选一致同意 DONE**才放行，否则继续执行。模型自己的候选分歧可提示“不应立即结束”，但这种投票并非外部语义验收器。
2. **按模型失败分布选择控制组件。** Qwen3-VL-8B、Qwen3-VL-30B-A3B 的精确动作重复率分别为 **32.12%**、**29.79%**，OpenCUA-7B 仅 **7.09%**；OpenCUA 却表现出更多候选分歧。因此作者分别启用循环恢复、或“循环恢复+DONE 门禁”、或仅 DONE 门禁。对 OpenCUA-7B 的 100 步配置，一致同意策略将任务成功率由 **26.06%** 提升至 **30.60%**，多数投票只有 **27.24%**；但更谨慎的结束判断也会增加耗尽步数的失败。
3. **小幅收益需要和执行成本一起看。** 在排除八个 Google Drive 任务后、包含 **361 个 OSWorld 任务**的评测中，三种本地模型、50/100 步预算对应的平均绝对成功率提升为 **2.01–4.54 个百分点**。例如 Qwen3-VL-30B-A3B 50 步条件下由 **35.31%→38.80%**；该配置 Prompt Token 多 **19%**，任务平均执行时间 **359.0→396.1 秒（约 +10%）**。实验主要是桌面 GUI 任务，未证明同法可直接迁移到云端大型 Coding Agent 或复杂多代理系统。

> **核心启示：** 对长流程 Agent，可以在可观测的重复动作与提前停止点加选择性控制；但**候选一致并不能替代实际任务状态、测试结果或人工验收**。

## 今日思考

两篇论文处理不同层级的失效：**ClonAct 管理“哪个任务该看到哪些上下文，以及多个任务的结果能否安全合并”；CANDID 管理“当前任务的下一步是否陷入循环，以及是否有足够理由宣布结束”。** 两者都把一部分可靠性问题从 Prompt 和模型权重，转移到可测量、可审计的 Harness 控制面。

可以抽象成一条实验链：

**Task Intent → Isolated Context Cell → Constrained Actions → Loop/Termination Gate → Trial Merge & Regression → Independent Acceptance**

值得进一步验证的是：在同一个多任务 Git 仓库实验中，将任务级隔离与动作级重复检测分开做消融，记录最终联合测试通过率、错误任务串扰、错误停止、Prompt 缓存账单和墙钟时延。**这是一项待验证的结合方案，不是两篇作者已联合证明的系统。**

**证据边界：** ClonAct 的并发案例主要来自程序化构造的任务、有限重复运行，显著性和两级定价存在限制；CANDID 的成功率是在固定本地模型与 OSWorld 环境下报告，终止门禁不能保证语义任务真正完成。文中数值不是任意 Agent 平台的普适提升率。
