## 1. Harness as a Language: A Minimalist Agent Framework With Maximal Expressivity

- **作者/来源：** Zhening Li、Joshua Liu、Mateja Vukelic、Nicole Shen、Supriya Lall、Amitayush Thakur、Alex Zhang、Omar Khattab、Jonathan Light、Armando Solar-Lezama / MIT CSAIL
- **发布日期：** 2026-09-22
- **arXiv：** https://arxiv.org/abs/2609.26891
- **AlphaXiv：** https://www.alphaxiv.org/abs/2609.26891

**推荐理由：** 这篇不是继续往 agent framework 里增加 memory、planner、router 和 workflow graph，而是反过来问：**如果把 harness 压缩到一个足够强的语言原语，多少高级 Agent 能力可以由模型自己编程出来？** JAZ 的核心只有一个 invoke：模型可以写任意可执行代码、递归调用新的 invoke，并把当前输入和执行历史当作程序变量。它把 long-horizon memory、subagent delegation 和 self-improvement 从外置系统重新解释成一种可编程 control flow。

**核心要点：**

- **Context 不再只是 prompt，而是程序状态。** JAZ 把用户输入、数据、工具以及 REPL interaction history 都暴露成代码变量；当 context window 接近上限时，Agent 可以把历史、进度摘要和下一步一起传给新的 invoke，形成 tail-recursive delegation。
- **一个足够通用的 primitive 可以替代一部分专门 harness。** 在 StuLife 的 far-recall 子集上，JAZ 达到 **69.9%** pass rate，而 Letta 为 **61.8%**；报告成本分别约 **$18.3 vs $42.1**。在 AppWorld continual self-improvement 上，JAZ TGC 为 **74.2%**，ACE 为 **69.9%**。
- **真正值得关注的是 harness API 的抽象层级。** 很多今天被写死在 framework 里的 orchestration 逻辑，可以下沉成少数通用原语，再由模型在运行时组合；平台应重新区分 runtime primitive、policy/hook 与固定 workflow。

> 核心启示：**Harness 设计的目标未必是把 workflow 描述得越来越完整，而可能是提供一组足够强、可组合、可约束的 primitives，让 Agent 自己生成 workflow：programmable context + recursive execution + hooks/policy。**

## 2. Build your way: Use any AI agent of your choice in Android Studio

- **作者/来源：** Matthew Warner / Android Developer Experience, Google
- **发布日期：** 2026-09-24
- **原文：** https://android-developers.googleblog.com/2026/09/build-your-way-use-any-ai-agent-in-android-studio.html

**推荐理由：** Google 这篇展示了一个越来越清晰的 AI-native IDE 架构：**Agent 可以替换，但 IDE 提供的 code intelligence、project graph、build diagnostics、emulator、skills 和权限模型保持稳定。** Android Studio 的 Bring Your Own Agent 通过 ACP 同时接入 Claude Agent、Codex、Google Antigravity 等 Agent，把“模型/Agent”与“工程环境”解耦。

**核心要点：**

- **IDE 正在成为 Agent 的共享 harness，而不是单一助手的 UI。** Android Studio 通过 ACP 把 project graph、build setup 和 platform details 提供给不同 Agent；Agent 自己再筛选当前任务需要的文件和细节。这样 codebase awareness 与 token efficiency 由 IDE/runtime 层统一提供，而不是每个 Agent 各自重新实现。
- **Tooling 应作为 IDE-native capability 注入。** 接入的 Agent 可以直接使用 build diagnostics、Jetpack Compose Preview、Android SDK 工具和 emulator control，并执行读写文件、shell、tests、web search 以及 subagent delegation。真正可复用的资产因此是环境能力和工具接口，而不是某个模型专属插件。
- **多 Agent 共存要求 session/context 与权限可迁移。** BYOA 支持不同 ACP-compatible Agent 接管任务，同时保留 workflow continuity、project skills、slash commands 和 memory；日常动作可以自动执行，风险更高的动作停下来请求批准。未来 IDE 更像一个 Agent operating environment，而不是绑定单一模型的 coding assistant。

> 核心启示：**团队级 coding harness 可以把 Agent 当成可插拔执行后端：IDE/project context + deterministic tooling + permissions + persistent session 保持稳定，Claude/Codex/其他 Agent 通过统一协议接入。真正应该标准化的是环境和上下文接口，而不是要求所有人使用同一个 Agent。**
